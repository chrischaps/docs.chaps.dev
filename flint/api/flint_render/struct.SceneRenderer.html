Expand description

Renders a FlintWorld to the screen

Fields§

§ocean_time: f64

Time in seconds driving wave phases. Set by the player each frame from the game clock — the same clock scripts see via total_time(), which is what keeps script-side ocean_height() queries in sync with the GPU.

§camera_offset: [f32; 2]§ortho_height: f32§aspect_ratio: f32§scene_dir: Option<PathBuf>

Scene directory for resolving relative font/texture paths

§pixels_per_point: f32

Physical pixels per logical point of the window it draws into: the OS scale factor. Styles sized in points (ASCII cells, #265) scale by it. Hosts with a window set it; 1 headless.

§grass_time: f32

Time in seconds, used for grass wind animation. Set by the player before render().

pub fn set_grass_ground( &mut self, device: &Device, queue: &Queue, config: &GrassConfig, ground: &GrassGround<'_>, ) -> Result<(), String>

Grow grass on a game’s own ground instead of a Flint terrain (ADR 0089): a density mask and a height over a world rectangle.

Replaces whatever grass is loaded, a terrain’s included, and can be called again whenever the ground changes. config is used as for a terrain, except that density_layer and density_source don’t apply: the mask is the density. Does nothing, and returns Ok, when the device has no compute grass (see has_grass_pipeline).

Source

pub fn update_grass_mask( &mut self, queue: &Queue, x: u32, y: u32, width: u32, height: u32, bytes: &[u8], ) -> Result<(), String>

Repaint part of the grass ground’s mask in place (ADR 0093): the width × height texels at (x, y), from bytes (one a texel, row by row toward +Z). The buffers and bind groups stay as they are, so a small clearing costs a small upload, not a reinstall.

Errs when no ground was set with set_grass_ground (a terrain’s grass has no mask to repaint), or when the rectangle runs off the mask or bytes is the wrong length. On a device with no compute grass it does nothing, as set_grass_ground does.

pub fn load_procedural_mesh( &mut self, device: &Device, name: &str, vertices: &[Vertex], indices: &[u32], material: ImportedMaterial, )

Create or replace the named mesh from raw vertex/index data.

Any entity whose model.asset is name draws it from the next update_from_world. Replacing a mesh frees the old GPU buffers once the current frame’s draw lists let go of them, so a mesh can be rebuilt as often as needed without growing GPU memory. Vertex colours are used when material.use_vertex_color is set; they are linear, so convert sRGB colours with crate::srgb_to_linear.

pub fn set_gpu_timing( &mut self, device: &Device, queue: &Queue, on: bool, ) -> bool

Time the frame’s phases on the GPU, or stop (ADR 0108): the grass compute, the shadows, the scene, the post-process chain, its last pass (the composite, or FXAA when it’s on) and the world lines, each a scope, into RenderStats::gpu_passes. Off by default. The device must have been created with Features::TIMESTAMP_QUERY (Flint’s contexts ask for it where the adapter has it); without it timing stays off. Returns whether timing is on.

The host ends each frame with finish_gpu_timings, after its last timed submission.

Call between frames, never with a frame’s passes half encoded: an MSAA change rebuilds every scene pipeline and its targets, a shadow-resolution change the shadow maps, and a render scale change the HDR chain. Only what changed is rebuilt, so calling it every frame with the same settings costs nothing.

  • render_scale sets the scene’s scale as set_render_scale does (a player stepping the scale itself keeps calling that; render_scale_auto is the player’s and ignored here).
  • msaa: 1 or 4 samples for the scene passes.
  • shadows, shadow_resolution, shadow_cascades, shadow_distance.
  • post_process, bloom, ssao, ssao_samples, fog, volumetric cap the post config: off turns the effect off, on leaves it as set.

pub fn set_msaa(&mut self, device: &Device, samples: u32) -> u32

Draw the scene passes with samples MSAA samples, 1 or 4 (anything else is 1, with a warning). Rebuilds every scene pipeline, whose sample count is baked in, and drops the MSAA targets so the next frame makes them at the new count. Bind groups, meshes and textures are kept: the new pipelines are made against layouts equal to the old ones, which wgpu (and WebGPU) treat as the same layout.

pub fn ensure_style_resources(&mut self, device: &Device)

Build the pipelines of every stylize pass the config switches on that isn’t built yet (#262). Every frame does this itself; calling it after setting a config moves the shader compile off the first frame that draws the style. A style’s textures are made on that frame.

Building runs under catch_unwind because some GPU drivers (Intel Skylake) crash with unrecoverable device loss compiling these shaders; a style that fails stays off and marks the device lost.
