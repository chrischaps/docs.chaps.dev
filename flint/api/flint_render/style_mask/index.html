Module style_mask 

Source
Expand description

The entity style mask (#263): a per-pixel style id that says which style, if any, drew each pixel, so a style pass can stylize chosen entities and leave the rest of the scene alone.

An entity asks for a style with the style_mask component:

[entities.barrel.style_mask]
style = "ascii"

Its descendants inherit the style unless they carry a style_mask of their own; enabled = false takes an entity and its subtree out again.

§Per-entity settings (#266)

A style that takes settings per entity names a component of its own (StyleDescriptor::component, ascii_style for ASCII). Its fields are the style’s parameters and options, and any it leaves out come from the scene’s [post_process.styles.<name>] table, then the style’s defaults:

[entities.barrel.ascii_style]
ramp = "blocks"
tint = [1.0, 0.7, 0.3]   # a 3-array fills a style's tint_r/g/b

Each distinct set of settings is a StyleVariant with an id of its own, so entities that say the same thing share an id and a pass reads the settings of every pixel’s id from one small table. A style whose grid option is object gets one variant per styled root, anchored at that root’s world origin. enabled = false on the component is an opt-out variant: it keeps the entity out of that style even where the style covers the whole screen. A plain style_mask { style = "ascii" } is the same as an empty ascii_style.

§How the mask is drawn

The ASCII spike (#261) measured the two ways to write it and chose a redraw over a new attachment on every scene pipeline. After the scene pass (and the MSAA depth resolve), each visible opaque draw of a styled entity is drawn again into one Rg16Uint target at scene resolution, with its cached transform bind group (and, for skinned meshes, its bone bind group), so the per-entity loop makes no buffer and no bind group. There’s no depth attachment: each fragment tests itself against the frame’s single-sample depth with a tolerance of its own depth slope, so the mask works at any render scale and the scene pipelines don’t change.

Under MSAA (#306) the mask is drawn 4x instead, into a multisampled target of its own, each covered sample testing itself against that sample of the scene’s multisampled depth, and a resolve folds it into the single-sample mask with any styled sample beating the empty ones. Drawn at pixel centres against the sample-0 depth, a feature about a pixel thin (a bench seat’s edge at a grazing angle) lost the pixels the scene’s samples gave it, and an outline style drew the gaps.

Each draw’s id goes into one dynamic-offset uniform buffer, uploaded in a single write a frame. The mask target lives in the post chain’s StyleTargets, so a resize drops it with every bind group over it, and it is only made, and only drawn, while a style that reads it is on (StyleDescriptor::uses_mask) or the style debug view is showing.

§Blending in and out (#278)

A blend field on the style component (or the style_mask) draws the entity with that much of the style, 0 to 1. It rides in the mask beside the id (the .g channel), not in the variant, so a script ramping it every frame keeps the entity’s id and makes no new variant. A style mixes its own pixel with what it was given by that amount; ASCII can also dissolve, turning that share of its cells.

§What’s in front: the veil (#290)

Transparents and particles write no depth, so a depth-tested redraw alone would leave a styled stone masked where fire or glass sits in front of it, and the style would glyphize the fire as stone. Just before the mask, a veil pass draws every visible transparent mesh (static and skinned) and every particle into an R8Unorm target, depth-tested against the scene with no depth write, each with the alpha it is drawn with (an additive particle by its alpha times its brightest channel), “over” blended so layers add up to their combined coverage. The mask then writes each styled pixel’s blend times what the veil leaves uncovered. The rule: what’s in front unmasks by its coverage. A style that honours the blend (ASCII, user styles through flint_style_blend) shows the fire as fire and the stone through any uncovered share; a fully covered pixel keeps its id at blend 0. A transparent that is itself styled is left out of the veil: it is in the mask itself, as a lens (below).

§Terrain and transparents (#310)

Terrain chunks are masked when the terrain’s entity (named by SceneRenderer::set_terrain_entity) is styled: they use the standard Vertex and transform layout, so the static pipeline draws them as is.

A styled transparent is a lens. Its draws come after every opaque one, back to front as the scene drew them; they write no depth, but each fragment still tests against the opaques’ depth, so where one shows it is the nearest styled surface and its id replaces what’s behind it. The style then draws the whole pixel, glass and what’s seen through it.

Particles, sprites, grass and water stay unmasked (particles and unstyled transparents only veil): grass is instanced, and the others write no depth.

LegendEntry

StyleIds
The styles entities ask for, numbered from 1 in name order. Ids change only when the set of names does, and are the same for the same scene on every run (no entity id or hash order goes into them).
StyleMaskPass
The mask’s pipelines and its per-draw uniform buffer, made the first time a frame needs the mask.
StyleVariant
What one style id stands for (#266): the style that draws it and the settings its entities give that differ from the scene’s.

Constants§

BLEND_FIELD
The field of a style component (or style_mask) that says how much of the style an entity is drawn with (#278): 0 is its own shading, 1 the style’s, anything between a mix (a cross-fade, or for ASCII’s transition = "dissolve" the share of cells that have turned).
BLEND_ONE
The mask’s .g for a blend of 1: the style fully on.
INITIAL_MASK_SLOTS
The per-draw slots the mask’s uniform buffer starts with (4 KB, #311). A frame with more styled draws grows it to the next power of two, so a scene pays for the draws it has and every one of them is masked.
MSAA_SAMPLES
The scene’s sample count the mask matches under MSAA.
NO_STYLE
The id of a pixel no style drew.
SLOPE_TOLERANCE
How far behind the scene’s depth a mask fragment may be, in multiples of its own depth slope (fwidth(z)). The spike’s value: it absorbs the rasterisers’ small disagreements (and, under MSAA, the half pixel between the centre’s depth and a sample’s) without letting a hidden face through.
STYLE_MASK_COMPONENT
The component an entity names its style in.
STYLE_MASK_FORMAT
The mask’s format: one style id a pixel in .r, 0 where no style drew, and the entity’s blend in .g (#278), 0..=BLEND_ONE for 0..1. A reader that only wants the id reads .r, as it did when the mask was R16Uint.
VEIL_FORMAT
The veil’s format: one blendable coverage a pixel.
