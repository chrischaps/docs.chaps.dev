Module stylize

Stylize passes (#262): one interface for Kuwahara, ASCII, watercolor, pencil and whatever comes after them.

A style is a module in this directory that exports a StyleDescriptor named STYLE, plus one name in [register_styles!] at the bottom of this file. The descriptor says where the style sits in the chain (StyleStage), which parameters it takes, when it is on, and how to build its pipelines; the StylePass it builds records its draws for one frame from a StyleFrame. Everything else is the framework’s:

  • Pipelines are built the first time a style is switched on (StyleSet::ensure, from SceneRenderer::ensure_style_resources), under catch_unwind, since some drivers crash compiling a shader. A style that fails stays off and the renderer reports a lost device.
  • Targets. Each stage hands a style its input and an output to draw into, ping-ponging between two targets the framework owns, so styles chain. A style’s own intermediates come from StyleFrame::target. All of them live in StyleTargets inside the post chain’s resources, which resize_postprocess() rebuilds, so no style has a resize hook of its own and none can keep a stale view.
  • Bind groups are cached with the chain (the same BindCache the rest of the post chain uses, #139), and samplers come from the chain’s shared linear sampler: a style’s bind groups hold no sampler of their own beyond that one, which keeps the DX12 sampler heap safe.
  • Config. A style reads its parameters from PostProcessConfig::styles, which a scene sets with [post_process.styles.<name>]; the F4 Rendering & Effects menu draws its sliders from the descriptor. Kuwahara predates the table and keeps its own kuwahara_* fields.

§Order

Styles of one stage run one after another, each reading the one before it, in the order their tables give (order = <n> in [post_process.styles.<name>], #299; chain_order). A style without one stands at its registration index, so a scene that says nothing runs in registration order; ties keep registration order too. The stages sit at two fixed places in the post chain:

scene (HDR, render scale)
  -> style mask (Rg16Uint: id + blend, while a style reads it; #263, #278)
  -> shared edges (Rgba16Float, depth's size, while a style needs them; #301)
  -> Hdr styles (Kuwahara)                 linear Rgba16Float, scene resolution
  -> SSAO, volumetric, bloom (read the scene depth / original HDR)
  -> composite: fog, DoF, bloom add, tonemap, grade, vignette, grain, render modes
  -> Display styles (ASCII, pencil, invert) surface format, output resolution
  -> FXAA
  -> surface

§The entity style mask

A style that stylizes only chosen entities sets StyleDescriptor::uses_mask and reads StyleFrame::mask: one id a pixel, the entity’s style_mask style (StyleFrame::style_id finds the style’s own), drawn after the scene pass (crate::style_mask). mask_view is the example, and the style debug view.

A per-entity style (StyleDescriptor::component, #266) goes further: an entity’s own component switches it on and carries its settings, each distinct set an id of its own, read with StyleFrame::variants. ASCII is the example.

§Shared inputs

Some inputs cost enough that two styles computing their own would double the bill. A style lists them in StyleDescriptor::needs and the framework makes each once a frame, for every style on that asks: StyleNeed::Edges is the geometry edge texture (edges, #301), handed over as StyleFrame::edges. edges_view draws it, and user styles get it with inputs = ["edges"].

An Hdr style is shaded by what follows it: fog fades it, bloom haloes its bright parts, the grade tints it (Kuwahara’s painterly look wants that). A Display style sees the finished picture at output resolution, after the render-scale upscale, which is where the ASCII spike found glyphs have to be drawn to stay crisp (#261, finding 7). SSAO and bloom read the unstylized HDR; that is deliberate for now (the light comes from the scene, not the brush strokes).

Modules§

catalog
What styles exist and what they take, for agents and people (#303): flint render --list-styles prints catalog_text, and with --json the catalog as JSON. Everything comes from the registry’s descriptors, so a new style (built-in or a styles/<name>.shader.toml once custom::load_dir has run) appears with no change here.
custom
User-authored styles (#274, ADR 0112): a game describes a style in styles/<name>.shader.toml and writes one WGSL function beside it.
edges
Shared geometry edges (#301): one edge texture a frame, for every style that asks for it.
kit
The building blocks most styles are made of: a full-screen triangle pipeline, the two bind group shapes the post chain uses, a uniform buffer and the pass that draws one triangle. With these a style is mostly its shader and its uniform struct.
