Module custom 

Source
Expand description

User-authored styles (#274, ADR 0112): a game describes a style in styles/<name>.shader.toml and writes one WGSL function beside it.

# styles/duotone.shader.toml
version = 1
name = "duotone"
label = "Duotone"
stage = "display"          # or "hdr"
shader = "duotone.wgsl"
inputs = ["depth"]         # colour is always there; also "mask", "edges"

[params.mix]
default = 1.0
min = 0.0
max = 1.0
help = "How far to the two inks"
// styles/duotone.wgsl
fn style(p: StylePixel) -> vec4<f32> {
    let l = flint_luma(p.color.rgb);
    return vec4<f32>(mix(p.color.rgb, vec3<f32>(l), params.mix), 1.0);
}

The framework writes everything else: a prelude with the bindings, the params struct (one f32 per declared parameter), helpers (flint_sample, flint_view_depth, flint_style_blend, …) and the entry points. At the display stage p.color and the returned colour are display values (what the eye sees) on any target format: the prelude decodes and encodes an sRGB target, so a user never meets the gotcha the built-ins work around by hand.

The composed module is parsed and validated with naga before wgpu sees it (natively), and an error comes back as file:line:col in the user’s file. A style that fails draws its input unchanged (a passthrough) and its error is kept for the host to show (errors). The WGSL is polled for changes (natively, a few times a second) and rebuilt in place; an edit that fails keeps the last good build drawing.

The registry is append-only ([super::register_runtime]): a style keeps its index for the run. An edited .shader.toml is read again by reload_changed (#275), which hosts call a few times a second: the new descriptor takes the old one’s index ([super::replace_runtime]), the renderer builds it again on the next frame, and the host re-reads the scene’s settings for it (refresh_settings).

load_dir
Register every *.shader.toml in scene_dir’s style folders that isn’t registered yet. Call it before the scene’s [post_process] is read, or its tables name an unknown style. Returns one message for each file that couldn’t be loaded (and each warning a check raised); a style whose shader fails still registers, drawing a passthrough.
load_file

params_size

prelude
The prelude for source: everything before the user’s first line.
refresh_settings
Re-read the settings of each style reload touched from authored (the scene’s [post_process], parsed again now that the registry knows their new parameters) into config, leaving every other style as the host has it (#275).
reload_changed
Hot reload of the descriptions (#275), natively: read again every loaded .shader.toml whose modified time moved, and load any new one in scene_dir’s style folders. A description that no longer reads keeps the style as it was and shows the error (errors); one that does replaces the style at its registry index, so the renderer builds it again on the next frame. The WGSL itself is polled by the pass, so a shader edit needs nothing from the host.
report_build_panic
Record that style name’s pass panicked while it was built (the renderer caught it): it stays off, and its error says so.
source
The source a loaded user style was read from.
style_dirs
The folders a scene in scene_dir finds styles in: its own styles/, then its parent’s (a game’s levels/ beside styles/), as models are.
