Flint’s mixer in the browser’s audio thread (#136).

The web player mixed on the main thread: cpal’s WebAudio host asks for each buffer from an onended callback, so on a phone the mix took about a third of the frame and every long frame made a buffer late. This crate is a second, small wasm that runs kira inside an AudioWorkletProcessor instead. It knows nothing of Flint: the page posts it sounds (as samples) and one batch of protocol::Commands a frame, and the processor asks it for 128 frames at a time.

Mixer is plain Rust, tested natively; exports is the C ABI the processor’s JS calls (crates/flint-audio/src/worklet.js). The wasm is built on its own, with only kira: trunk runs cargo build -p flint-audio-worklet --target wasm32-unknown-unknown --profile worklet before each build (crates/flint-player/Trunk.toml).
