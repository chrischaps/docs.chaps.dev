Expand description

Hooks an embedding game installs with PlayerApp::add_extension.

Extensions run in the order they were added. All methods default to doing nothing, so an extension implements only what it needs.

fn register_script_api(&mut self, _engine: &mut Engine)

Register native functions, types or modules on the script engine.

Called once, from add_extension. The engine outlives scene transitions, so registrations persist for the whole run. Flint’s own API is registered first; a function registered here with the same name and parameter types replaces the engine’s.

The engine uses rhai’s sync feature, so registered closures and the state they capture must be Send + Sync (Arc<Mutex<_>>, atomics).

fn pre_update(&mut self, _ctx: &mut ExtensionCtx<'_>)

Per-frame Rust, run after the clock ticks and before the scripts’ on_update, so anything written to the world here is visible to scripts in the same frame.

fn on_window_event(&mut self, _event: &WindowEvent) -> bool

See a window event before the player does. Return true to consume it. Only input events (keyboard, IME, mouse buttons, wheel, cursor movement, touch) can be consumed; lifecycle events such as Resized, CloseRequested and RedrawRequested always reach the player whatever this returns. The first extension to consume an event stops it reaching later extensions.

egui sees events first (see ui): input it wants, such as typing in a focused text field or a click on an egui window, never arrives here.

fn on_key(&mut self, _key: &KeyInput<'_>) -> bool

See a key go down or up before the player does: a real one, or one an --input-script plays (ADR 0103). Return true to consume it, as for on_window_event.

A scripted key has no winit KeyEvent (nothing outside winit can build one), so it never reaches on_window_event. Read keys here and a capture can press them. A real key comes here straight after this extension’s on_window_event passes on its KeyboardInput, so handle a key in one hook or the other, not both. Keys winit can’t name (PhysicalKey::Unidentified), and the synthetic presses winit sends for keys held as the window gains focus, come only to on_window_event.

egui sees keys first, as it does window events: a key typed into a focused field never arrives here.

fn ui(&mut self, _ctx: &Context)

Draw the game’s own egui UI. Called every frame from inside the player’s egui pass, after the scripts’ on_draw_ui and before the debug panels, so it draws over the script HUD and under the panels.

Installing any extension routes window events through egui first. An event egui wants is consumed, and extensions, the player and scripts never see it: keys and IME while a widget has keyboard focus (a TextEdit being typed in, so Escape there unfocuses the field rather than quitting), and clicks and the wheel over an egui area. Clicks on empty space still reach the game.

Use windows and areas, or side and top panels. A CentralPanel covers the whole window, so it takes every click from the game.

fn fonts(&mut self, _defs: &mut FontDefinitions)

Add to or change egui’s fonts before the player installs them (ADR 0081). defs already holds the project’s fonts/ (each file under its stem, the fonts.toml aliases, and its [egui] defaults).

Called whenever the player sets egui’s fonts: at start, on a scene change into another project root, and when an extension is added after the fonts are in. Fonts set here survive those reloads, which fonts set with Context::set_fonts from ui do not. A named family added here is one scripts can draw in too.

Families exist from the first egui pass after the call, so laying text out in one from ui is safe on every frame.

fn debug_panels(&self) -> Vec<String>

Name the game’s own debug panels (ADR 0107). Each joins the engine’s (grass, ocean, camera, …): F3 opens and closes it with them, and it docks in their columns under its name. The player asks when it builds its panels, on each scene load and when the extension is added, so a name given later appears at the next scene load. Empty, the default, adds none.

Only a player built with its debug-hud feature (the default) has debug panels. Without it this is never called.

fn debug_panel_ui(&mut self, _name: &str, _ui: &mut Ui)

Draw the contents of the debug panel name, one that debug_panels named. Called every frame while the panel is open, after ui, so it reads the game’s state as ui left it. The heading and the scrolling are the player’s.
