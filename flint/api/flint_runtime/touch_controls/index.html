Module touch_controls 

Source
Expand description

On-screen touch controls (#133): virtual sticks, buttons, a menu button and a look-drag region, declared in the input config’s [touch_controls] block and drawn by the player.

Why config and not a script: a stick is an input device, not game UI. It has to be hit-tested before egui sees a finger, feed actions that are bound only to keys, and answer within the frame the finger moves, none of which a script’s on_draw_ui can do. So the block layers with the rest of InputConfig (built-in -> game -> user -> CLI), the logic lives here beside InputState, and the player paints what TouchControls::widgets reports. Scripts still compose the game’s HUD; they can ask touch_controls_visible() to make room for the controls.

Geometry is authored in logical points (egui’s, the draw_* space), from an anchor at a screen edge or corner, inside the safe-area insets. Touches arrive in physical surface pixels; TouchControls::set_metrics gives the pixels-per-point and insets that join the two. The scene’s render scale never matters: the HUD is drawn at full resolution.

The controls show only once a real finger has touched the screen, and hide when a key or gamepad takes over, so a desktop player never sees them. Each control holds the finger that grabbed it by touch id, so a stick and a button work under two thumbs at once.
