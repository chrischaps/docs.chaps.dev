The procgen cache’s disk tier (#181): outputs kept between runs.

The in-memory ProcGenCache only helps on a revisit within one run; without this tier every launch of the player regenerates every procgen texture and mesh (about 3 s of a 4 s start on showcase_game/levels/tavern_hub.scene.toml). Underneath it, each output is kept as one file in a directory, usually <project>/.flint/procgen-cache/.

  • The key is whatever the memory cache is keyed on, the spec’s hash (which the resolver folds the generator’s name and revision into) and the seed, plus this file format’s own version. Bump a generator’s revision and the next launch misses on every spec it builds, then regenerates.
  • Seed::Random never reaches the disk. A random spec changes on each run, which is the point of it.
  • Reads go through flint_core::vfs, writes through std::fs: a file is written beside its final name and renamed into place, so a crash or a second player mid-write never leaves a half file under a real name.
  • Size cap, LRU on mtime. A hit touches the file’s modification time; a write that takes the directory over its budget removes the files least recently touched until it fits.
  • A file that doesn’t decode (a different format, a truncated write, a type whose layout changed) is a miss, and is removed.

Native only. The web player has no disk to keep it on, so there DiskCache::open returns None and the tier is never there.
