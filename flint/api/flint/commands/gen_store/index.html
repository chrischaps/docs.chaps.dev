Module gen_store 

Source
Expand description

flint gen --register: put generated files in the content store, record where they came from, and find them again.

Each registered run leaves three things behind:

  • the bytes, in the content store at .flint/assets/<2 hex>/<hash>.<ext>;
  • a sidecar beside each output file, <file>.asset.toml, carrying the provenance (generator and its revision, spec hash, seed, timestamp, Flint version);
  • a provenance entry at .flint/procgen/<spec hash>/<seed>.toml listing the hashes that spec + seed produced.

The entry is what makes the cache a property of the store rather than of whatever happens to sit at the output path: a later run with the same spec and seed finds it, checks the files on disk against its hashes, and copies back from the store any that were deleted or changed, without generating.

The spec hash covers the spec’s bytes, not the code that reads them, so the entry also records the generator’s revision: an entry made by another revision (or by a Flint that didn’t record one) is stale, and the run regenerates and says why.
