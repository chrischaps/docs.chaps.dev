flint_audio::remote

Expand description

What the main thread tells the worklet’s mixer (#136).

The page and its AudioWorklet share no memory (GitHub Pages can’t send the headers SharedArrayBuffer needs), so the engine’s calls become Commands, written into one byte batch a frame and posted to the worklet, which applies them to its own kira. Sounds cross separately, once each, as samples. Every id is made on the main thread, so a call returns its handle at once and never waits for an answer.

This file has no dependencies: flint-audio includes it with #[path] to write batches, and the worklet crate reads them, so both sides are always built from the same encoding.
