How steadily a browser audio stream is fed (#101, #136).

The main-thread stream asks for each buffer from the main thread and schedules it to start where the one before it ends. A buffer’s slack is how far ahead of the audio clock it was scheduled; negative slack means its start had already passed, which leaves a gap you hear as a click.

The worklet (BufferMeter::worklet) is called by the audio thread itself, so there is nothing to schedule. What it can lose is time: when it misses its deadline, the audio clock falls behind the wall clock for good. Its slack is a buffer’s length minus how far the clock has fallen behind its steadiest, so negative slack means more than a buffer of sound went missing.

BufferMeter keeps that per buffer and turns it into console lines. It has no platform code, so its arithmetic is tested on the desktop.
